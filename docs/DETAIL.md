# DeepSight 深度推理研究法 · 插件说明

## 它做什么

把 DeepSight 方法论拆成三层装进 DeepSeek Harness：

1. **知识层** —— 方法论本体是 skill（`deepsight`），**随包分发**在 `skills/deepsight/`，由 `index.js` 用 `ctx.skills.register()` 注册进本 preset 的层。装完即用，不依赖任何外部绝对路径。
2. **纪律层** —— 一个 `deepsight` agent preset，把 Phase 0.0 / 0.1 / 0.2 / 1 / 2 / 3 的强制顺序写进 persona。
3. **算力层** —— 三个工具（契约 / 审计 / 趋势）加一个出口闸门，只负责方法论里算不住也守不住的那一小块。

## 三个工具

### `deepsight_contract`

开跑前锁定本次研究的验收契约，返回 `runId`：

- 按**决策落点**选框架（八选一）；`auto` 时按信号词路由，全部未命中则按消歧规则退到行业研究
- 定模式：`light` 轻量（2 轮追问 + 1 轮对抗）或 `deep` 深度（完整四步 + 可选 Council）
- 定证据阈值：`[B]` 占比上限（默认 70%）、`[C]` 目标区间（默认 20–35%）
- 按问题里的战略转向信号词判定是否**必须**先做 Phase 0.0 反方论证
- 随契约返回证据等级口径与 Council 触发规则，避免研究途中口径漂移

### `deepsight_audit`

提交结论账本，返回确定性判定：

- `[A]/[B]/[C]` 条数与占比
- `[B]` 占比超过上限 → `returnForRegrade`（退回重标）
- 独立模型族数 `D`；`D < 3` → 终审证据级封顶 `[B]`
- 标记 `conflict: open` 的结论 → 冲突未闭环
- **来源链追溯（v0.4 新增）**：`actionClaimIds` 里的每条结论必须在 `claims` 里用 `basisClaimIds` 声明来源（一级观察用空数组 `[]`）。工具沿来源链做传递闭包，任一路径出现 `[C]` → 决策刹车；行动依据**未声明来源**或**引用了未知结论** → 同样拦下。命中的 `[C]` 源头在 `cSources` 里列出。
- `[C]` 占比触发 Phase 2 Council 的判定
- 最终 `verdict`：`pass` / `return` / `block`

> **为什么要做成来源链**：v0.3 的刹车只检查「`[C]` 是否直接出现在行动依据」。实测发现模型会把由 `[C]` 级 TAM 派生的可竞标市场规模标成 `[B]`，再用这座「B 标签的桥」把推算数字接进决策——标签合规，刹车失效。改成追溯来源后，要在不触发拦截的前提下绕过，就得伪造整条来源链，成本与暴露面完全不同。

占比与封顶由工具计算，不交给模型心算——这是它存在的理由。

每次 `deepsight_audit` 都会把这次判定追加一行到账本文件，并返回 `ledgerPersisted` / `ledgerPath` 说明是否写成。**写失败不影响判定结果**，只在返回值里报告。

落点解析顺序：

1. 环境变量 `DEEPSIGHT_LEDGER_DIR` —— **推荐写进 `$DSH_HOME/.env`**，随 profile 生效
2. 兼容旧名 `DSH_DEEPSIGHT_DIR`（只能用系统环境变量设置，见下）
3. 兜底 `$DSH_HOME/deepsight`

> ⚠️ **绝对不要把 `DSH_` 开头的变量写进 `$DSH_HOME/.env`。** 该前缀是 DSH 的保留命名空间，只允许启动环境设置；写进 `.env` 会让 DSH **拒绝启动**，报 `only the launching environment may set`。需要放进 `.env` 的路径请用 `DEEPSIGHT_LEDGER_DIR`。

**包内不含任何个人路径。** 想把它接到 Obsidian 归档目录，只需把 `DEEPSIGHT_LEDGER_DIR` 指过去。

### `deepsight_trend`

只读账本，汇总跨报告趋势：

- 记录数、`pass` / `return` / `block` 分布
- 平均证据分布、平均独立模型族数、Council 触发次数
- 按框架归并：次数、被判 block 次数、平均 `[C]` 占比
- 最近 N 条记录（`days` 可按天过滤，`limit` 1–20）
- 损坏行计数跳过而不是让整次读取失败；超过 2000 行只读最近 2000 行并标 `truncated`

这个工具回答的是「**这套纪律到底改变了什么**」——`[C]` 占比有没有真的降下来、刹车有没有真的咬到、哪个框架最容易被判 block。不要靠翻旧对话统计。

传 `write: true` 时，结果会**覆盖写入**同目录的 `DeepSight-审计趋势.md`（带 YAML frontmatter 与 `deepsight` 标签，Obsidian 里可直接检索），工具渲染里会回一行笔记路径。笔记开头注明「自动覆盖写入，手改会被下次覆盖」，所以不要在笔记里写手工批注——要写就写到旁边的独立文档里。

## 出口闸门

`verdict = block` 时，本 preset 内的 `present` 调用会被拒绝，直到违规结论被降级或冲突闭环。闸门**只在明确判定为 block 时**生效，不要求每次交付都先做一次审计仪式。

**`pass` 的含义要限定清楚**：它只表示「没有 `[C]` 级结论直接、或经 `basisClaimIds` 派生进入行动依据」。它**不表示证据充分**，也不表示标签正确。交付物抬头应当照实写出这句话，不要让读者把 `pass` 当成背书。

## 三次实测：这道刹车到底管什么

这套机制不是设计出来的，是三次实测逼出来的：

| 版本 | 测试题 | 结果 | 学到什么 |
|---|---|---|---|
| v0.3 | 「未具名股票该不该买」（无证据 + 强要建议） | 未触发 | 模型用「拒绝」守住了，**测试没测到刹车**——拒绝本身是个合法 `[B]` 结论 |
| v0.3 | 禁检索 + 强制给规模的「MCP 网关该不该建队」 | **被绕过** | 把 `f([C])` 的派生市场规模标成 `[B]` 直接引用；闸门只查直引，看不见派生 |
| v0.4 | 同一道 MCP 题 | **合法放行** | 模型主动把 8 条 `[C]` 隔离出决策链，9 条行动依据全部声明来源；闭包无 `[C]`，独立重算一致 |

**仍未覆盖的一点**：`[B]` 的起锚。模型可以凭空声明一条 `[B]`「一级观察」（如「单客户交付 6–10 周」这类经验估计），为任意决策接一根干净来源。严格按方法论，经验类推应算 `[C]`；但 `[B]` 与 `[C]` 的边界在方法论本体里并未操作化，加字段只是把自报往前推一层，堵不住认真想绕的人，却会显著增加正常使用摩擦。**这是有意接受的设计边界，不是待修缺陷。**

## 用法

1. 在**新会话**里把 Agent 模式选为 **DeepSight 深度推理研究法**
2. 抛出需要深度推理的问题；Agent 会先调 `deepsight_contract`
3. 过程中每步用 `deepsight_audit` 提交结论；交付前最后一次必须是 `pass`
4. 想积累趋势时，在 DeepSight 会话里调 `deepsight_trend`（`write: true` 会落一份 Obsidian 笔记）

## 边界（务必阅读）

- **刹车管的是「来源链完整性」，不是「标签正确性」。** 它能证明「行动依据没有从 `[C]` 派生而来，且来源已声明」，不能证明「每条 `[B]` 确实是 `[B]`」。后者只能靠人读报告。
- **闸门是概率性约束，不是硬保证。** Harness 没有机制拦截最终散文；模型仍可以绕过工具直接下结论，或用 `write` 代替 `present`。它的真实作用是让"跳过"留下可审计的痕迹，而不是让跳过不可能。
- **账本落盘但只追加，不索引。** 每行是一条审计判定；`deepsight_trend` 每次全量读最近 2000 行再聚合。到十万行量级时需要换成按需查询，现在不需要。
- **vault 里的 JSONL 会随每次审计增长，是 git 追踪的对象。** 如果不希望它进版本库，在 vault 的 `.gitignore` 里加 `08-知识库/演进判据/deepsight-ledger.jsonl`；可读的趋势笔记 `DeepSight-审计趋势.md` 建议保留追踪。
- **账本不记结论原文**，只记编号、档位、占比与判定，避免把未公开的研究内容写进长期文件。`question` 截断到 300 字。
- **兼容性只看 `engines.dsh`。** 本插件声明为纯 JS、零依赖，不引入版本闸风险。
- **`D` 值来自调用方自报**（`council.modelFamilies`）。工具算得准，但前提是模型如实填报——这一点与方法论本体一样，依赖纪律。
- **Phase 3 交付层未实现。** 报告模板、飞书导入管线等交付细节仍由 skill 与既有 `lark-*` / `office` 技能承担，本插件不重复。
- **skill 正文来自上游仓库** `github.com/deeparchi-ai/deepsight`，其自身存在两处已知断链（`references/feishu-delivery-pipeline.md`、`references/chinese-walled-garden-extraction.md`），本插件未修补。

## 安装与更新

- 方法论内容随包分发在 `skills/deepsight/`；上游仓库（`github.com/deeparchi-ai/deepsight`）只作为同步来源
- 更新方法论：拉上游 → 跑同步脚本 → **重启 DSH** 重新注册 skill
- 修改 `index.js` 后需重启以加载新的模块代次
- `engines.dsh` 声明为 `^0.2.2-rc.3`；DSH 主版本变化时需重新验证 preset 内部插件行是否仍存在
